## 2026-08-07 - CLAUDE.md's dashboard doc never followed the last-5 fix, and the fix itself is incomplete

*Status: `Proposed`*

**Observation:**

Commit `bab1be6` (2026-08-05, "Show last 5 unchecked tasks instead of first 5 on project cards") deliberately changed `parseNextSteps` from first-5 to last-5, specifically to stop stale early-phase tasks from outranking active later-phase work. That was the right instinct, but two things never got closed out:

1. The "Project Dashboard Compatibility" section in CLAUDE.md — copied verbatim into every project's own CLAUDE.md, including this repo's — still says the dashboard "pulls the first 5 unchecked `- [ ]` lines." Nobody updated the template or any existing project copy after the code changed. Any project owner reading their own CLAUDE.md today gets told the wrong thing.
2. Last-5 only trades one failure mode for a related one. It was verified against `8.-Magic-Band` on 2026-08-07: that project's Phase 3 is marked `*(PAUSED)*` but sits before Phase 4, the true active phase — and Phase 4's own heading was stale (`*(Not yet started)*` despite being 4/6 done). Last-5 pulled stale Phase-3 items ahead of/alongside real Phase-4 work for exactly the reason bab1be6 was trying to avoid. Raw file-order position (from either end) is not a reliable proxy for "current work" once paused/future phases are interleaved with an active one.

**Suggested change:**

1. Make `parseNextSteps` phase-aware: skip phases whose heading is marked `PAUSED`/`Future`, and prefer unchecked items from the most-advanced phase that has at least one checked item (a proxy for "currently active"), falling back to file order only within that phase.
2. That heuristic is only as good as phase-status labels. Add a rule to Work Package Conventions / Session End Routine: the phase heading must be updated the moment the first item in that phase is checked off, so labels don't go stale while work is actually happening (as happened on Magic-Band's Phase 4).
3. Once the logic is corrected, update the "Project Dashboard Compatibility" section in the template's CLAUDE.md to describe the corrected (phase-aware) behavior, then propagate the wording to existing project CLAUDE.md copies (this repo's own, Magic-Band's, BetterGolfLeagueTracker's, etc.) — don't just swap "first" for "last," which is already known to be an incomplete fix.

Tracked as backlog items in `3. Work Packages.md` (WP1.4).
