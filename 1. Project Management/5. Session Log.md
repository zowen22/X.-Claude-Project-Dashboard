## 2026-09-14 - Phase-Aware Next-Steps Fix + Project Picker
_Status: `COMPLETED`_
_Type: `Manual`_

### What Was Done
- User asked why `8.-Magic-Band`'s card kept showing "Confirm relay type..."
  and "Design or source floor power box..." long after both were obsolete.
  Traced it to two separate causes: (1) Magic Band's own PM files never got
  updated after the 2026-06-16 decision to replace the relay + floor box
  with a 433MHz RF outlet — fixed on that repo's side, PR #7
  (`zowen22/8.-Magic-Band`); (2) a real dashboard bug — `sectionIsDead`
  only checked a line's *immediate* heading, so a plain sub-heading (e.g.
  Magic Band's `### WP3.1`) under a `*(PAUSED)*` phase reset back to
  "alive," leaking stale items from paused phases. This is the exact gap
  PR #2 flagged on 2026-08-07 and Magic Band's own PDR #5 hit again on
  2026-08-13.
- Fixed: `headingVerdict()` now returns `null` (inherit) instead of `false`
  (alive) when a heading has no marker of its own; `parseNextSteps` tracks
  a level-aware stack so dead/alive status cascades down to child headings.
  Mirrored the same change in `test/next-steps-reference.py` and
  regenerated `test/expected-next-steps.txt` against live repo content
  (drift there is expected — see the test file's own header comment).
- Along the way, found `BetterGolfLeagueTracker` in `PROJECTS` was a stale
  repo name (renamed to `3.-Better-Golf-League-Tracker` on GitHub).
  Existing card rendering still worked (GitHub redirects old names for
  both the REST API and raw content fetches), but it silently broke exact
  string matching in the new picker below — fixed to the canonical name.
- Built the requested project picker: a "Manage Projects" (⚙) panel next
  to Refresh, listing every repo on the GitHub account (fetched live via
  `/users/{user}/repos`) with checkboxes. Selection is saved to
  `localStorage` per-browser and drives which repos `init()` fetches —
  independent of the `DEFAULT_PROJECTS` fallback list.
- Verified: script parses cleanly (`node -e new Function(...)`), the
  Python reference implementation matches the JS change exactly
  (`--check` passes), the persistence/render logic was unit-tested in
  isolation (Node, mocked `localStorage`), and the GitHub repos-list
  endpoint was hit directly to confirm the picker's data source works.
  Did not run a live browser test — this sandbox's npm registry access is
  read-only, so Playwright couldn't be installed this session.

### Decisions Made
- Picker selection lives in `localStorage`, not a config file — it's a
  per-browser display preference, not shared project state.
- Saving with everything unchecked is allowed (dashboard already handles
  zero registered projects gracefully); the picker doesn't silently
  re-default to avoid overriding explicit user intent.
- Left the CLAUDE.md "Project Dashboard Compatibility" doc-sync (WP1.4,
  last item) open rather than propagating changes across every project's
  CLAUDE.md copy in this session — scoped down to what was asked.
- Closing PR #2 (`pm-hygiene-log`) as superseded — its core ask (phase-
  aware next-steps) is done here, differently than originally sketched.

### Blockers / Issues
